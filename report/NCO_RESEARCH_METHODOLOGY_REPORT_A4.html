NCO Research Methodology and Calculation Framework

เอกสารรายงานฉบับ A4 สำหรับอธิบายหลักการวิเคราะห์ ตัวแปรนำเข้า ขั้นตอนการคำนวณ เหตุผลเชิงสถิติ และฐานอ้างอิงเชิงวิชาการของระบบ NCO/HR Blueprint ตาม implementation ปัจจุบัน

ขอบเขตรายงาน

Data quality, HNI, profession mix, WCI, denominator, workload pressure, Need_FTE, gap, specialty recommendation, confidence scoring

สถานะเชิงวิธีวิจัย

Hybrid decision-support model ที่ผสาน need, workload, capacity, outcome และ governance

สาระสำคัญ: ระบบนี้ไม่ใช่สูตรจัดอัตรากำลังเชิงกฎหมายโดยตรง และไม่ใช่ WISN เต็มรูปแบบ แต่เป็นโมเดลช่วยตัดสินใจเชิงกำลังคนที่ปรับตามภาระสุขภาพของประชากร ภาระงานบริการจริง ศักยภาพกำลังคน ผลลัพธ์บริการ และความน่าเชื่อถือของข้อมูล เพื่อหลีกเลี่ยงการสรุปปัญหาว่าเกิดจาก “ขาดคน” เพียงสาเหตุเดียว

วัตถุประสงค์และประเด็นหลักของรายงาน

  1. อธิบายว่าระบบใช้ข้อมูลใดบ้างและตัวแปรใดมีผลต่อการคำนวณ
  2. อธิบายขั้นตอนคำนวณตั้งแต่ data quality gate จนถึง recommendation
  3. อธิบายเหตุผลเชิงสถิติและเหตุผลเชิงระบบบริการที่อยู่เบื้องหลังแต่ละสูตร
  4. แยกให้ชัดว่าอะไรเป็น external evidence และอะไรเป็น internal provisional benchmark

กรอบคิดหลัก 5 ชั้น: need-based logic, capacity-based logic, workload-based logic, outcome-based validation และ governance/confidence logic ซึ่งสอดคล้องกับกรอบ structure-process-outcome ของการประเมินคุณภาพบริการสุขภาพ

ขอบเขตการประยุกต์ใช้

รายงานฉบับนี้ใช้สำหรับภาควิธีวิจัย ภาคเครื่องมือ ภาคผนวกเชิงเทคนิค และการชี้แจงที่มาของ recommendation ในระบบ NCO/HR Blueprint โดยเน้น calculation path ที่ระบบใช้งานจริง ไม่ได้เสนอการ refactor architecture หรือเปลี่ยนแหล่งข้อมูลนอกขอบเขต implementation ปัจจุบัน

กรอบแนวคิดเชิงวิธีวิจัย

นิยามเชิงวิธีวิจัย: ระบบนี้เป็น hybrid, workload-calibrated, need-capacity-outcome decision-support model สำหรับการวิเคราะห์กำลังคนโรงพยาบาล โดยผสาน burden ของประชากร ข้อมูลบริการจริง สัดส่วนกำลังคน ผลลัพธ์บริการ และ governance metadata เข้าด้วยกัน

แกนหลักของโมเดล

  • Need-based: elderly, chronic, mental burden
  • Capacity-based: headcount และ profession mix
  • Workload-based: OPD, IPD, ER, OR, delivery, mental, chronic
  • Outcome-based: A-H outcomes และ service plan indicators
  • Governance: source, year, completeness, scope, audit

โครงสร้างตีความ

  • Structure: workforce, benchmark, denominator scope
  • Process: workload, referral flow, coding quality, pathway
  • Outcome: mortality, CMI, BOR, referral leakage, specialty metrics

ฐานอ้างอิงเชิงแนวคิดจากภายนอก

โดเมนหลักการที่นำมาใช้แหล่งอ้างอิงหลัก
Workforce planningการประเมินกำลังคนควรผูกกับ workload และ skill mix มากกว่า headcount ratio ล้วนWHO WISN
Health systemsการประเมินบริการต้องดู building blocks และบริบทระบบ ไม่อ่าน staffing แบบแยกขาดจากระบบบริการWHO health systems building blocks
Quality measurementต้องอ่าน structure, process, outcome ร่วมกันAHRQ, National Academies, Donabedian lineage
Routine data qualityการตัดสินใจเชิงบริหารต้องมี data quality review ก่อนตีความWHO RHIS / DQA toolkit
Population burdenAgeing, NCD และ mental burden เป็นแรงขับสำคัญของ demand และ skill mixWHO Ageing, NCD, Suicide, ICOPE, Rehabilitation

ข้อควรระบุในงานวิจัย: แม้ฐานคิดของระบบสอดคล้องกับ evidence ภายนอก แต่ค่า benchmark หลายตัวที่อยู่ในระบบปัจจุบันยังเป็น internal provisional seeds และไม่ควรอธิบายเกินจริงว่าเป็น national staffing standard ที่รับรองแล้ว

ขั้นตอนคำนวณ ส่วนที่ 1

Data Quality, Denominator, HNI, Mix

ขั้นที่ 1-4: Data Quality, Denominator, HNI, Profession Mix

ขั้นที่ 1: Data Quality Gate

ระบบตรวจ G01-G04 ก่อนเพื่อป้องกันการตีความผลจาก administrative/coding data ที่ผิดพลาด หาก data quality fail อย่างน้อย 1 ตัว ผลลัพธ์จะยังคำนวณได้ แต่ recommendation ควรถูกตีความแบบ provisional

ขั้นที่ 2: Clinical Denominator

Workload proxy:

`outpatient_visits + 12*inpatient_visits + 1.5*emergency_visits + 20*surgery_count + 15*delivery_count + 1.2*mental_health_visits + 1.1*chronic_disease_visits + total_workload_score`

วิธี denominatorตรรกะเหตุผล
`amphur_population`ใช้ประชากรพื้นที่รับผิดชอบโดยตรงเหมาะกับหน่วยที่ burden หลักมาจาก catchment เดิม
`province_workload_blend`ใช้ max ระหว่าง amphur, province floor 30%, และ workload proxy x 1.20 แล้ว cap ไม่เกินจังหวัดรองรับบทบาท referral ของโรงพยาบาลจังหวัด/ศูนย์
`network_zone_workload_adjusted`ใช้ max ระหว่าง amphur กับ workload proxy x 1.10 แล้ว cap ไม่เกิน 60% ของจังหวัดรองรับ general hospital/network hub
`workload_population_proxy`ใช้ประชากรเทียบเท่าจาก workloadลด bias จากการใช้ทะเบียนประชากรอย่างเดียว

ขั้นที่ 3: Health Need Index (HNI)

Reference defaults: elderly = 30, chronic = 25, mental = 5000 ต่อ 100,000

Normalization: `norm = clamp(actual/reference, 0, 1.5)`

Weights: elderly 40, chronic 40, mental 20

Formula: `HNI = ((normE*wE)+(normC*wC)+(normM*wM))/total_weight * 100`

เหตุผลของ HNI คือการรวม need-side burden หลายมิติไว้ใน composite เดียว โดยใช้ bounded normalization เพื่อป้องกันค่าผิดปกติรบกวน index ทั้งระบบ

ขั้นที่ 4: Profession-sensitive need mix

วิชาชีพสูตร raw weight ที่ใช้จริง
Doctor`28 + 18*norm_chronic + 8*norm_elderly`
Nurse`28 + 12*norm_chronic + 10*norm_elderly + 6*norm_mental`
Pharmacist`10 + 8*norm_chronic`
Physical therapist`8 + 10*rehab_pressure + 6*norm_elderly`
Psychologist`8 + 10*norm_mental + 4*suicide_pressure`
Clinical psychologist`6 + 10*norm_mental + 6*suicide_pressure`

จากนั้นระบบ normalize raw weights เป็นสัดส่วนรวม 100% เพื่อใช้เป็น need-sensitive mix ใน WCI และ Need_FTE engine

WCI, Burden Multiplier, Workload Pressure, Need_FTE

ขั้นที่ 5-8: Capacity, Workload Pressure และ Need_FTE

ขั้นที่ 5: Workforce Capacity Index (WCI)

Ratio รายวิชาชีพ: `ratio_i = (headcount_i / population) * rate_per`

Score รายวิชาชีพ: `score_i = min(140, (ratio_i / target_i) * 100)`

Composite: `WCI = sum(score_i * mix_pct_i / 100)`

วิชาชีพTarget ต่อ 10,000Default weight
doctor_total3.532
nurse_total12.038
pharmacist_total1.510
physical_therapist_total0.88
psychologist_total0.46
clinical_psychologist_total0.26

ขั้นที่ 6: Burden multiplier

`burden_multiplier = clamp(0.75 + HNI/100, 0.75, 1.6)` ใช้ให้ HNI ทำหน้าที่เป็น moderating factor ไม่ใช่ตัวครอบสูตรทั้งหมด

ขั้นที่ 7: Workload function pressure

Profession signalสูตรที่ใช้จริง
Doctor`0.30*ipd + 0.25*er + 0.25*or + 0.20*delivery`
Nurse`0.35*opd + 0.25*ipd + 0.20*er + 0.20*delivery`
Pharmacist`0.45*opd + 0.55*chronic`
PT`0.60*ipd + 0.40*or`
Psych / Clinical Psych`mental_per_10k` เป็น signal หลัก

ทุก signal ถูกคำนวณจาก intensity ที่เทียบ actual rate ต่อ reference rate และ clamp ระหว่าง 0 ถึง 2 จากนั้นแปลงเป็น profession-specific pressure factor ด้วยช่วง lower-upper bounds ที่ต่างกันตามวิชาชีพ

ขั้นที่ 8: Need_FTE

`baseline_need_fte = target_value * effective_population_total / rate_per`

`mix_adjustment = max(0.65, actual_mix_pct / default_weight_pct)`

`pressure_factor = base_pressure_factor * workload_pressure_factor`

`need_fte = baseline_need_fte * burden_multiplier * mix_adjustment * pressure_factor`

`available_fte = headcount * fte_per_headcount`

`gap_fte = max(0, need_fte - available_fte)`

`suggested_add = ceil(gap_fte)` ในเชิงตรรกะ implementation ปัจจุบันใช้สูตรปัดขึ้นแบบใกล้เคียง

เหตุผลเชิงระบบบริการ: สูตร Need_FTE ถูกออกแบบให้สะท้อนทั้ง demand base, burden profile, skill mix และ service workload พร้อมกัน จึงเหมาะกับบทบาท decision-support มากกว่าการใช้ headcount ratio เดี่ยว ๆ

ขั้นตอนคำนวณ ส่วนที่ 3

Gap, Outcome Validation, Specialty, Confidence

ขั้นที่ 9-12: การตีความผลลัพธ์และความเชื่อมั่น

ขั้นที่ 9: Need-Capacity Gap

Gap score: `gap = HNI - WCI`

เกณฑ์: red ถ้า > 20, yellow ถ้า > 0, green ถ้า <= 0

แนวคิดคือ HNI แทนแรงกดดันฝั่ง demand และ WCI แทนความเพียงพอฝั่ง capacity เมื่อ HNI สูงกว่า WCI มาก แปลว่าภาระนำหน้าศักยภาพกำลังคน

ขั้นที่ 10: Outcome validation

รูปแบบผลลัพธ์การตีความ
Gap สูง + Outcome แย่มีความเป็นไปได้สูงว่าขาด capacity ร่วมกับ process issue
Gap สูง + Outcome ดีระบบอาจยังพยุงตัวได้ แต่เสี่ยง over-stretched ต้องเฝ้าระวัง
Gap ต่ำ + Outcome แย่มีแนวโน้มเป็น process/protocol/referral/data quality issue มากกว่าขาดคนอย่างเดียว

ขั้นที่ 11: Service plan specialty deep dive

เมื่อ specialty indicator ผิด threshold ระบบจะคำนวณ severity จากระยะห่างจาก threshold และแปลงเป็นจำนวนแพทย์/พยาบาลเฉพาะทางเพิ่มเติมตาม base demand ของแต่ละโรคหรือ pathway

`severity = (actual - threshold)/threshold` เมื่อ low is good

`severity = (threshold - actual)/threshold` เมื่อ high is good

`shortage_factor = 1.0, 0.7, 0.35` ตาม gap level red, yellow, green

`severity_factor = 1 + clamp(severity, 0, 2)`

`addDoc = ceil(baseDoc * severity_factor * shortage_factor)`

`addNurse = ceil(baseNurse * severity_factor * shortage_factor)`

Process-first rule: หาก overall gap เป็นสีเขียวและ severity ต่ำกว่า 0.40 ระบบจะไม่แนะนำเพิ่มคนทันที แต่ให้เน้น pathway/process review ก่อน

ขั้นที่ 12: Confidence scoring

ระบบให้คะแนนความเชื่อมั่นจาก source, year, scope, completeness และ audit availability สำหรับ PP และจาก source, scope match, dictionary, audit และ year note สำหรับ HR เพื่อให้ผู้ใช้รู้ว่า recommendation นี้ “น่าเชื่อถือแค่ไหน” ไม่ใช่แค่ “คำนวณออกมาเท่าไร”

จุดแข็งเชิงวิธีวิจัย

  • ผสาน need, capacity, workload, outcome และ governance ในโมเดลเดียว
  • ไม่ตีความ outcome โดยไม่ดู data quality และ process context
  • ให้ recommendation ระดับวิชาชีพและ specialty ได้
  • มี audit/replay และ benchmark governance table รองรับการตรวจสอบย้อนหลัง
  • ใช้ median และ percentile ในส่วนที่ต้องการ robustness ต่อ outlier

ข้อจำกัดที่ต้องระบุอย่างตรงไปตรงมา

  • benchmark หลายตัวเป็น `provisional internal seeds`
  • โมเดลยังไม่ใช่ WISN เต็มรูปแบบ เพราะยังไม่มี activity-time standards ครบทุก service task
  • ตัวแปรบางชื่อยังไม่สะท้อนหน่วยจริงเต็มที่
  • workload บาง function ยังพึ่ง manual-preferred หรือ manual-required source
  • HR year versioning ยังไม่ explicit ในทุก schema
  • outcome ยังอาจถูกรบกวนจาก severity mix, referral pattern และ practice variation
