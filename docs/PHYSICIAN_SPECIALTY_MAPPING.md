# NCO Physician Specialty Mapping — v1 (7 พฤศจิกายน 2569)

## ขอบเขตและระดับความพร้อม

เครื่องมือแยกแพทย์จากวิชาชีพ `doctor` (headcount รวม) เป็นรายการ **สาขาและอนุสาขา** สำหรับวิเคราะห์ Supply FTE, Service Workload และ Required FTE รายโรงพยาบาล/ปี โดย **ไม่เปลี่ยนสูตรหรือข้อมูลของ HR Blueprint เดิม**

- เปิดที่ `physician_specialty_mapping.html` หรือกดลิงก์ในส่วน Profession ของ HR Blueprint
- บัญชีอ้างอิงใน `data/physician_specialties_tmc.json`: 102 รายการจากบัญชีสาขาฝึกอบรมที่แพทยสภารับรอง (ประเภท 1 = 14, ประเภท 2 = 27, ประเภท 3 = 61)
- รหัส `TMC-1-01` ฯลฯ เป็น **รหัสภายในโครงการ** ไม่ใช่รหัสที่แพทยสภาออกให้ และไม่ได้บ่งชี้สิทธิรักษาหรืออนุมัติตำแหน่ง
- นำเข้าข้อมูลจาก CSV ที่ผู้มีหน้าที่รับผิดชอบทวนสอบแล้ว, คำนวณแยกตามสาขา, สร้างรายการข้อผิดพลาด, ส่งออกผลและ exception CSV ได้
- ไม่เชื่อมทะเบียนแพทย์รายบุคคล/ฐาน HROPS จริงโดยอัตโนมัติและไม่กำหนดอัตรากำลังมาตรฐานจากค่าตัวอย่าง ดังนั้นถือเป็น **data-mapping tool** ที่พร้อมให้พื้นที่ป้อนข้อมูลและทดสอบ ไม่ใช่ผลวิเคราะห์ที่รับรองระดับเขต

## รูปแบบไฟล์ที่ใช้

ดาวน์โหลด template CSV หัวตารางเปล่าได้จากหน้า UI ไม่ใส่ตัวเลขตัวอย่างเป็นข้อมูลจริง

### Supply CSV

`hospital_code,year,physician_key,specialty_name,specialty_code,fte,source,verification_status`

- `hospital_code`: 5 หลัก, `year`: ปี พ.ศ. (2400–2700 ตาม validation)
- `physician_key`: รหัสแทนบุคคล (pseudonymous, **ไม่ใช่** ชื่อ/เลขบัตร/ข้อมูลผู้ป่วย) โดยคนเดียวกันต้องใช้รหัสเดียวกันทุกสาขาและหน่วยงาน
- `specialty_name`: ชื่อตามแพทยสภา (ไทย/อังกฤษ) หรือชื่อดิบจาก `position_specialist_name` ใน HROPS/HIS; ถ้ามี `specialty_code` ระบบใช้รหัสนี้ก่อน
- `fte`: ส่วนเวลาปฏิบัติงานจริงในสาขานั้นต่อปี มากกว่า 0 ถึง 1; แพทย์คนเดียวที่ระบุหลายสาขาหรือหลาย รพ. รวม FTE ปีนั้นต้องไม่เกิน 1 (ถ้าไม่ทำงานสาขานั้น อย่าสร้างแถว FTE = 0)
- `source`: รหัสอ้างอิงรายงาน/ทะเบียนที่อนุมัติ ไม่ใช่ข้อมูลส่วนบุคคล
- `verification_status`: `Verified`, `Reviewed`, หรือ `Draft`
- เงื่อนไขวุฒิบัตร/การมอบหมายงาน/ด้านความเชี่ยวชาญ ต้องตรวจด้วยกระบวนการ HR จริง ไม่อนุมานจากคำว่าเป็นแพทย์

### Workload CSV

`hospital_code,year,specialty_name,specialty_code,activity_code,volume,volume_unit,minutes_per_unit,standard_unit,awt_minutes,cas_percent,ias_hours,source,workload_verification_status,standard_source,standard_verification_status,overlap_policy`

- ใช้ **workload ที่สาขานั้นปฏิบัติงานจริง** และ `activity_code` ที่ไม่ซ้ำในสาขา–โรงพยาบาล–ปีเดียวกัน; ห้ามเอา Total OPD ของโรงพยาบาลลงหลายสาขาซ้ำ
- `volume` เป็นจำนวนจริงที่มี source; `volume_unit` ต้องสอดคล้องกับ `standard_unit` เช่น `visits` คู่ `minutes/visit`; `minutes_per_unit` ต้องมีที่มาจากมาตรฐานเวลาที่ได้รับการทวนสอบ
- `awt_minutes` = นาทีเวลาทำงานพร้อมให้บริการต่อปี; `cas_percent` = ร้อยละกิจกรรมสนับสนุน; `ias_hours` = ชั่วโมงกิจกรรมเพิ่มต่อปี; ต้องกรอกแม้เป็นศูนย์ที่ **มีหลักฐานตรวจสอบ** และใช้ค่าเดียวกันสำหรับทุกกิจกรรมในสาขา–ปีนั้น
- `overlap_policy`: `independent`, `exclusive` หรือ `deduplicated`; ห้าม `unknown` เมื่อต้องคำนวณ
- `workload_verification_status`, `standard_verification_status` = `Verified` / `Reviewed` / `Draft`

### Crosswalk CSV (optional)

`raw_specialty_name,specialty_code,verification_status,approved_by,source`

นำชื่อสาขาไม่ตรงกันจาก HROPS หรือ HIS มาผูกกับรหัสภายในได้ **เฉพาะ** แถวที่ `Verified`, มีผู้อนุมัติและแหล่งอ้างอิง โดยไม่ใช้การ match แบบ fuzzy ที่อาจจับผิดสาขา Crosswalk ที่ขัดแย้งกับชื่อมาตรฐานจะถูกปฏิเสธ

## สูตรและคำเตือนการตีความ

```text
Service minutes = Σ(verified specialty workload volume × activity standard minutes)
Required FTE = (Service minutes / AWT) × [1 / (1 − CAS%)] + (IAS hours × 60 / AWT)
Supply FTE = Σ(physician assigned FTE fractions to that specialty/year)
Gap FTE = Required FTE − Supply FTE
```

- `VERIFIED`: supply/workload/standard มี source, unit/overlap ถูกต้อง, ไม่เกิน 1 FTE/แพทย์/ปี และสถานะ Verified; **มิใช่คำรับรองความแม่นยำ หรือการอนุมัติตำแหน่ง**
- `PROVISIONAL`: คำนวณเชิงสำรวจได้ แต่ข้อมูลมีอย่างน้อยหนึ่งส่วนยังไม่ Verified; ห้ามเสนอเป็นกรอบอัตรากำลังที่อนุมัติทันที
- `BLOCKED`: ข้อมูล supply/workload หายไป, unit ไม่ตรง, source ไม่ครบ, ผิดกติกา, นับซ้ำ หรือ FTE รวมเกิน 1; ช่อง FTE/GAP เป็นค่าว่าง **ไม่ใช่ 0**
- หากข้อมูลสาขาบางส่วนไม่ได้ส่งเข้าระบบ หรือมีชื่อสาขาที่จับคู่ไม่ได้ แผนระดับโรงพยาบาล/เขตยังถือว่า **ครอบคลุมไม่ครบ** แม้บางแถวจะ Verified

## จากผลจำลองไปสู่ข้อเสนอเชิงบริหาร

| ผลตรวจ | ข้อเสนอเพื่อพิจารณา | เงื่อนไขที่ต้องตรวจ |
|---|---|---|
VERIFIED และ gap เป็นบวก | เสนอวิเคราะห์ช่องว่างตาม Service Plan, การจัดบริการเครือข่าย, แผนเพิ่มสมรรถนะ/ฝึกอบรม/สรรหา | เทียบกรอบอัตรากำลังและอำนาจอนุมัติ, HROPS, งบประมาณ, service-mix และภาระเวร |
VERIFIED และ gap เป็นลบ | ทบทวนภาระงาน, การใช้เวลาร่วม, teleconsultation, rotation หรือ support network | ไม่ให้ย้าย/เกลี่ยบุคคลโดยอัตโนมัติ; ตรวจตำแหน่ง/คำสั่งและสิทธิการปฏิบัติงาน |
PROVISIONAL | ขอทวนสอบ workload และมาตรฐานเวลาโดยทีมวิชาชีพ | ระบุผู้รับรอง source, วิธีสุ่มตรวจ และปีงบประมาณ |
BLOCKED | แก้ฐานข้อมูล/ข้อกำหนดสาขาและรหัสโรงพยาบาลก่อน | ห้ามสรุปจำนวนแพทย์ที่ต้องเพิ่ม/เกลี่ยจากแถวนี้ |

การจัดสรร/เกลี่ย/ปรับปรุง/กำหนดระดับตำแหน่งเป็น **การตัดสินใจของผู้มีอำนาจตามระเบียบ** ไม่ใช่ผลคำนวณจากระบบ ต้องเสนอแยกตามสาขาวิชาชีพและแนบเอกสารหลักฐานแต่ละกรณี

## การทดสอบและการวัดความแม่นยำ

- `node --test tests/physician_specialty_mapping.test.mjs` — ตรวจ catalog, CSV, WISN, source gate, crosswalk, duplicate และ sum FTE
- ยัง **ไม่มีข้อมูลจริงระดับโรงพยาบาล–สาขา–ปีและชุดเปรียบเทียบที่ผ่านการทวนสอบใน repo** จึงไม่สามารถรายงาน `MAE/MAPE` หรือความแม่นยำเป็นร้อยละได้
- เมื่อผู้มีอำนาจจัดข้อมูล aggregate ที่ผ่านการตรวจแล้ว ให้ทดสอบอย่างน้อย 1 ปีฐาน + ปีถัดไป โดยเทียบ FTE need กับผล workload/time-motion ที่รับรอง แยกสาขา/ระดับโรงพยาบาล พร้อมรายงาน MAE, bias, coverage และ MAPE เฉพาะ denominator ที่ไม่เป็นศูนย์
- CMI data source `output/cmi_5y/health_kpi_records.json` ยังว่างใน main ณ วันที่ออกเอกสาร จึงห้ามอ้างว่าผลทำนายได้รับการ validate จาก CMI ครบ 5 ปี

## การเปิดเผยข้อมูล

ระบบอ่าน CSV ในเบราว์เซอร์เพื่อคำนวณ **ไม่ส่งไฟล์ขึ้นเซิร์ฟเวอร์**; ผลและข้อผิดพลาดดาวน์โหลดเฉพาะ aggregate/รหัสแทนบุคคลที่ไม่ระบุตัวตน แต่ควรใช้รหัสแทนบุคคลที่สร้างจากระบบที่มีสิทธิ์ ไม่คัดลอก HN, CID, ชื่อแพทย์/ผู้ป่วย หรือข้อมูลผู้ป่วยรายบุคคลขึ้น GitHub

## Name-first CheckMD assisted verification (7 พ.ย. 2569)

1. กรอกชื่อ–นามสกุล และคลิกเปิดเว็บ https://checkmd.tmc.or.th/v3 เพื่อค้นหาที่ระบบแพทยสภาด้วยตนเอง (ยังไม่มี API ที่ได้รับอนุญาตหรือเชื่อมต่อใช้งานจริง)
2. คัดลอกข้อความผลตรวจจากเว็บแพทยสภาที่มีชื่อจริง การขึ้นทะเบียนและสาขา/อนุสาขา มาวางในหน้า `physician_specialty_mapping.html` ระบบอ่านชื่อและจับคู่กับบัญชีสาขา 102 รายการแบบ exact mapping; ไม่เดาสาขาที่ไม่ตรง
3. ระบุรหัสแพทย์ภายในที่เป็น pseudonym, รหัสโรงพยาบาล, ปีงบประมาณ, สาขาที่ **ปฏิบัติงานจริง** และ FTE ต่อสาขา (รวมแพทย์หนึ่งคนทุกสาขา/โรงพยาบาลใน session ไม่เกิน 1.0 FTE)
4. การยืนยันเองเป็นเพียง `Reviewed`; ไม่เลื่อนเป็น `Verified` จากข้อความคัดลอกเพราะปลอมแปลงได้ ต้องใช้ HR/ผู้รับผิดชอบอนุมัติจากทะเบียนจริงและมีเอกสารประกอบ ส่วนที่ไม่มีการรับรองอยู่ `Draft`
5. รายการ supply ที่บันทึกจะรวมในเครื่องคำนวณเดิม; ต้องนำเข้า workload รายสาขาที่ผ่านตรวจสอบก่อนจึงคำนวณได้ ไม่ใช้ผลตรวจใบอนุญาตแทนข้อมูลตำแหน่ง/เวลาทำงาน

ไม่มีการดึงข้อมูลผลตรวจจากเว็บแพทยสภาโดยตรง ไม่มีการ bypass CAPTCHA, ไม่มีการบันทึกชื่อแพทย์ไว้บน GitHub หรือส่งขึ้นเซิร์ฟเวอร์ และไม่มีการอ้างว่าระบบเชื่อม API แล้ว ข้อจำกัด: ชื่อ–สกุลแพทย์และผลคัดลอกประมวลผลเฉพาะใน browser session ส่วนหลักฐานใบอนุญาต/วุฒิบัตรต้องทวนสอบจากเว็บจริงและระบบ HR อีกครั้ง
